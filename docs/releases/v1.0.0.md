# v1.0.0

PVE WebUI Plugins 首个 1.x 正式版本，面向 Proxmox VE 9 提供独立容器运行的 WebUI 扩展宿主。沿用 PVE 的 ExtJS 界面和登录会话，扩展自身的数据与配置保存在独立数据卷，不修改 PVE 官方文件、VM/CT 配置或原生 API。

## 主要功能

- **部署入口内置。** 容器默认提供 Nginx HTTPS `8006` 网关与 HTTP `8008` 应用；宿主机默认端口相同，应用端口默认仅绑定 `127.0.0.1`。启动时自动生成代理配置和持久化自签证书，也可挂载自己的证书。关闭内置代理后，可将应用接入现有业务网关。
- **同集群多个 PVE 上游。** `PVE_UPSTREAM` 接受节点 IP 列表，首项为主节点，其余组成备用池。支持原生资源、API 和控制台 WebSocket 的转发，已发送的写入不自动重放。
- **统一模块与站点管理。** 在「--插件--」的一张原生表格中管理启停、显示别名、图标、混合排序及站点目标。附加站点内置启用，每个站点独立管理；Komodo 默认名称可自行设置别名。图标支持 PVE 原生类名和 URL，站点可自动发现图标。
- **原生导航与内置帮助。** 左侧树选择模块，中间竖向菜单切换介绍、基本配置和帮助文档，右侧显示内容。类型用颜色和文字区分，开发进度分别说明功能覆盖与成熟度。
- **独立插件生命周期。** 可选模块停用时不加载实现、不注册业务 API、不提供脚本、不初始化外部客户端或数据库。模块连接和凭据通过管理页保存。

## 本次修复

- 全局配置保存会保护尚未保存的 SafeLine 连接草稿；SafeLine 继续使用自己的保存和测试按钮。
- 明确的配置校验失败保留输入并允许修改后重试；修订冲突和结果未知仍要求重新读取核对。
- 视图选择器在聚焦、失焦和切换后保留图标留白，避免图标覆盖文字。
- 站点名称和别名中的特殊字符按原文显示，并在 HTML 渲染时转义。

## 部署与兼容性

本版面向全新部署，宿主私有配置采用 **schema 2**，旧配置和旧站点表结构不自动迁移。首次启动只启用内置附加站点；模块连接、启停和显示设置在管理页配置。部署时使用独立数据目录，保留原部署的备份。

默认上游连接使用 HTTPS，但 `PVE_TLS_VERIFY=false`；需要验证 PVE 服务身份时，配置 CA 与逐节点证书名称。备用节点必须属于同一 PVE 集群，已建立的响应和 WebSocket 会话不会自动迁移。

## 使用预构建镜像

GitHub Release 附带 `linux/amd64` 镜像归档、对应的 `.sha256` 校验文件，以及 `compose.yaml`、`env.example` 和 `compose.debug.yaml`。runtime 归档载入为 `pve-webui-plugins:1.0.0`，debug 归档载入为 `pve-webui-plugins:1.0.0-debug`。

在可连接 PVE 节点的 Docker 主机上，新建部署目录并下载 runtime：

```sh
mkdir pve-webui-plugins-1.0.0
cd pve-webui-plugins-1.0.0
release_base='https://github.com/sqkkyzx/pve-webui-plugins/releases/download/v1.0.0'
curl --fail --location --remote-name "$release_base/pve-webui-plugins-v1.0.0-linux-amd64.tar.gz"
curl --fail --location --remote-name "$release_base/pve-webui-plugins-v1.0.0-linux-amd64.tar.gz.sha256"
sha256sum --check pve-webui-plugins-v1.0.0-linux-amd64.tar.gz.sha256 && \
  docker load --input pve-webui-plugins-v1.0.0-linux-amd64.tar.gz
curl --fail --location --output compose.yaml "$release_base/compose.yaml"
curl --fail --location --output .env "$release_base/env.example"
```

确认校验和镜像载入均成功。编辑 `.env`，填写同一集群的 `PVE_UPSTREAM` 节点 IP 列表及 `PVE_ADMIN_USERS`，保留 `PVE_PLUGINS_IMAGE=pve-webui-plugins:1.0.0`，然后启动：

```sh
docker compose config --quiet
docker compose up -d --no-build --pull never
curl --fail --insecure https://127.0.0.1:8006/pve-plugins/health
```

浏览器访问 `https://Docker主机地址:8006`。默认入口使用自签证书，浏览器会提示证书信任或名称问题；上面的 `--insecure` 仅用于检查该默认入口。

开发调试归档名为 `pve-webui-plugins-v1.0.0-debug-linux-amd64.tar.gz`，校验文件为同名加 `.sha256`。debug 的源码挂载方式需要检出 `v1.0.0` 源码，并将 `PVE_PLUGINS_IMAGE` 指定为 `pve-webui-plugins:1.0.0-debug`，详见 README 的开发说明。

原生浏览器夹具使用 PVE 9.2.21。自动化测试、镜像 smoke 与真实登录后的业务验收分别核验，详细边界见[兼容性与发布验证](https://github.com/sqkkyzx/pve-webui-plugins/blob/v1.0.0/docs/wiki/Compatibility.md)。

安装步骤见 [README](https://github.com/sqkkyzx/pve-webui-plugins/blob/v1.0.0/README.md) 和[安装与双模式接入](https://github.com/sqkkyzx/pve-webui-plugins/blob/v1.0.0/docs/wiki/Installation.md)，模块能力与配置方法见[内置模块](https://github.com/sqkkyzx/pve-webui-plugins/blob/v1.0.0/docs/wiki/Modules.md)。
