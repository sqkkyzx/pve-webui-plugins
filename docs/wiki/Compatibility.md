# 兼容性与发布验证

## 1.0.0 配置契约

本版本采用全新部署方式。默认只启用内置附加站点，三个可选模块通过统一管理页启用和配置。

| 层次 | 当前契约 |
| --- | --- |
| 宿主私有配置 | schema 2，完整顶层结构与三字段导航 |
| 导航 | `entry_order`、`module_aliases`、`module_icons` 必须齐全，模块显示键限定为三个可选模块 |
| 站点存储 | 直接创建包含启用状态、别名和图标的完整表结构，读取前核验列集合 |
| 模块选择与服务凭据 | 由管理页及私有配置持久化 |
| 基础环境配置 | 同集群 PVE 节点 IP 列表、管理员、双模式网关、TLS 与注入开关 |
| 数据路径 | 统一数据目录内的 JSON 与各模块 SQLite |
| 默认网关 | HTTPS 8006，持久化自签证书，HTTP 应用 8008 默认发布到 `127.0.0.1:8008`，容器与宿主机端口一致 |

初始化使用独立的数据目录。旧配置格式会被明确拒绝，模块环境变量和旧来源文件也不再参与启动配置。

1.0.0 是扩展宿主的正式版本。Komodo 与 SafeLine WAF 的功能覆盖为「部分管理」，节点温度为「只读监测」，三个可选模块仍标识为「测试中」。附加站点显示「外部站点」，宿主不评定目标应用的成熟度。功能范围见 [[内置模块|Modules]]，主要变化见 [发行说明](https://github.com/sqkkyzx/pve-webui-plugins/releases/tag/v1.0.0)。

## 当前运行范围

桌面入口识别针对 PVE 9，原生浏览器夹具使用 PVE 9.2.21 的 ExtJS 与 CSS。其他 PVE 9 修订需要复核入口结构和被 override 的组件接口。

开发环境使用 Python 3.12、Node.js 20 或更新版本。容器以 UID/GID `10001:10001` 运行，使用只读根文件系统、runtime tmpfs 和独立数据挂载。

## 本版回归重点

- 首次启动为 sites-only，随后验证三个可选模块的 8 种组合。
- 无效初始配置在保存前拒绝，完整合并快照超过 256 KiB 时拒绝，磁盘与运行状态保持一致。
- Unicode 站点名称统一按码点计数，合法非 BMP 字符可以与普通站点共存。
- 异步站点菜单完成加载后恢复原生 PVE 视图状态，用户手动切换和当前会话优先。
- 旧 schema、旧导航字段、缺失导航字段和旧站点表结构按新契约拒绝。
- 正式镜像验证首次启动及 8 种组合，debug 镜像验证 Python、JavaScript、描述文件和模板重载。
- 实际镜像连接两个 HTTPS 模拟 PVE 节点，检查原生路由、WebSocket、主备切换和写入不重放。
- 验证默认自签网关证书重启保留，关闭代理后无 Nginx/容器 HTTPS 8006 服务，以及严格 CA 与逐节点 DNS 名称校验。
- 通过 HTTPS 的完整 Host/端口、Origin、PVE 票据与 CSRF 验证配置保存。
- 配置校验失败保留编辑草稿，冲突和结果未知仍要求重新读取；全局配置重载前保护尚未保存的 SafeLine 连接草稿。
- 视图选择器的图标留白在原生聚焦、失焦和视图切换后保留，站点名称与别名按纯文本显示。

发布记录应注明运行过的测试、实际镜像修订和目标服务版本。单元测试、镜像 smoke 与真实 PVE 登录验收分别记录。

## 已知验证边界

原生页面夹具与自动化测试覆盖界面交互和代理契约；真实 PVE 的完整登录、上传下载、noVNC 与终端流程仍需在目标部署逐项验收。SafeLine 9.4.2 CN 个人版的真实验收以读取为主，写入流程的自动化结果不能代替目标版本的实际验收。节点温度的可用传感器由硬件与驱动决定。各模块的具体限制在管理页的介绍、帮助文档及 [[内置模块|Modules]] 中列明。
