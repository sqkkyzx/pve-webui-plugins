## Komodo

Komodo 模块将 Core 中的服务器、应用栈和容器呈现在 PVE 风格的树与页面中，提供状态、日志、终端、操作记录和允许的资源操作。服务器与 VM/CT 的关联保存在宿主数据卷，关联后可进入相应对象下的 Docker 页面。

在基本配置中填写 Core origin、API Key、API Secret 和 TLS 设置，再点击顶部「保存并应用」。同一 Core 的凭据留空时保留已有值，更换 Core 地址需同时填写新的 API Key 与 API Secret。Core 与 Periphery 的运行环境、网络连通性和服务账号权限由各自部署负责。

终端使用 PVE 现有的 xterm.js 与同源插件 WebSocket，建立会话时检查外部权限与当前目标。离页时清理本次 PTY，连接或模块配置变更会终止插件连接。

「统计」「计划任务」包含占位页面，部署与代码仓库仍有未开放管理功能。应用栈配置、容器操作和终端会影响实际外部资源，界面中的确认与回执属于操作流程。详细功能见仓库的 `docs/KOMODO.md`。

## 节点温度

温度模块在 PVE 节点概要中显示 CPU、主板、磁盘温度和传感器明细。默认依据固定 PVE 上游提供的节点名称与 IP，读取节点的 node_exporter `hwmon` 指标。容器必须能够连接对应节点的 TCP 9100。

特定网络、TLS 或认证代理可在基本配置中为节点配置来源覆盖，窗口中点击「确定」后，再按顶部「保存并应用」。删除覆盖配置可恢复自动发现。数据缺失、过期和真实零值分别呈现，硬件传感器与驱动决定可用读数，跨硬件传感器识别需按实际节点核验。

对浏览器提供的接口为 `/pve-plugins/api/temperatures/nodes/{node}`。数据源安装与标签选择规则可参考仓库的 `TEMPERATURES.md`。

## SafeLine WAF

在管理页启用 SafeLine WAF 并保存，再于基本配置填写固定 HTTPS 管理 origin、API Token、TLS、可选证书主机名及 CA。执行连接测试后，点击「保存连接」持久化；测试操作本身不保存。Token 由后端持有，前端展示是否已设置的标记。

模块提供防护应用、黑白名单、TLS 证书、IP 组、事件、日志和统计，并为已经实现的配置提供编辑流程。规则匹配条件支持 AND/OR 草稿编辑，保存时检查连接修订、资源内容与操作回执。

当前标为「部分管理 · 测试中」。真实 SafeLine 9.4.2 CN 个人版验收以读取为主，写入流程已有自动化验证，仍需在目标版本逐项验收。目标 SafeLine 版本、版本授权和接口行为决定各项统计及筛选能力。部分个人版接口仅接受全站或特定时间范围，界面按可用能力呈现选项。尚未承诺完整替代官方管理控制台。

连接保存在统一数据目录的 `safeline.sqlite3`。当前入口与配置方法见实际管理页和仓库中的 `docs/SAFELINE-DESIGN.md`。

## 附加站点

附加站点由宿主内置提供，通过统一表格进行新增、编辑、删除和独立启停。站点可设置显示别名、自动或手动图标，并与模块混合排序。操作细节见 [[模块与站点管理|Configuration]]。
